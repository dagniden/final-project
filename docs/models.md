# Модели проекта

## 1. User

Кастомная модель пользователя на основе `AbstractUser`.

### Основные поля

| Поле          | Тип данных      | Required | Auto-filled | Описание                             |
| ------------- | --------------- | -------- | ----------- | ------------------------------------ |
| `username`    | `CharField`     | Да       | Нет         | Уникальное имя пользователя в системе |
| `email`       | `EmailField`    | Да       | Нет         | Email пользователя, используется как логин |
| `password`    | `CharField`     | Да       | Нет         | Хэш пароля пользователя              |
| `first_name`  | `CharField`     | Нет      | Нет         | Имя пользователя                     |
| `last_name`   | `CharField`     | Нет      | Нет         | Фамилия пользователя                 |
| `is_active`   | `BooleanField`  | Нет      | Да          | Признак активности учетной записи    |
| `is_staff`    | `BooleanField`  | Нет      | Да          | Признак сотрудника библиотеки        |
| `date_joined` | `DateTimeField` | Нет      | Да          | Дата регистрации пользователя        |

### Примечание

- Проект новый, поэтому кастомного пользователя лучше заложить сразу.
- Для текущей реализации аутентификация выполняется по `email`.
- В модели задано `USERNAME_FIELD = "email"`.
- Для MVP отдельная модель ролей не требуется: достаточно базового пользователя и сотрудника библиотеки через `is_staff`.
- При необходимости позже можно будет добавить, например, `middle_name`, `phone_number`, `role`.

### Поля

| Поле | Тип данных | Required | Auto-filled | Описание |
| --- | --- | --- | --- | --- |
| `id` | `BigAutoField` | Нет | Да | Уникальный идентификатор автора |
| `full_name` | `CharField` | Да | Нет | Полное имя автора |
| `birth_date` | `DateField` | Нет | Нет | Дата рождения автора, опционально |
| `death_date` | `DateField` | Нет | Нет | Дата смерти автора, опционально |
| `biography` | `TextField` | Нет | Нет | Краткая биография автора, опционально |

### Связи

- один `Author` может быть связан со многими `BookTitle`
- один `BookTitle` может быть связан со многими `Author`

## 4. BookTitle

Карточка книги в каталоге, без учета конкретного физического экземпляра.

### Поля

| Поле               | Тип данных                  | Required | Auto-filled | Описание                                      |
| ------------------ | --------------------------- | -------- | ----------- | --------------------------------------------- |
| `id`               | `BigAutoField`              | Нет      | Да          | Уникальный идентификатор карточки книги       |
| `title`            | `CharField`                 | Да       | Нет         | Название книги                                |
| `description`      | `TextField`                 | Нет      | Нет         | Описание книги, опционально                   |
| `publication_year` | `PositiveSmallIntegerField` | Нет      | Нет         | Год публикации, опционально                   |
| `isbn`             | `CharField`                 | Нет      | Нет         | ISBN книги, опционально, уникален при наличии |
| `publisher`        | `CharField`                 | Нет      | Нет         | Название издательства, опционально            |
| `language`         | `CharField`                 | Нет      | Нет         | Язык издания, опционально                     |
| `authors`          | `ManyToManyField`           | Да       | Нет         | Связь с авторами книги, минимум один автор    |
| `genres`           | `ManyToManyField`           | Нет      | Нет         | Связь с жанрами книги                         |
| `created_at`       | `DateTimeField`             | Нет      | Да          | Дата и время создания карточки                |
| `updated_at`       | `DateTimeField`             | Нет      | Да          | Дата и время последнего обновления карточки   |

### Связи

- один `BookTitle` может иметь много `BookItem`

### Примечание

- `BookTitle` хранит только общую информацию о книге.
- Физические экземпляры хранятся отдельно в `BookItem`.
- Для MVP обязательным считается `title`, а также минимум один связанный `Author`.
- Поле `genres` может быть пустым.
- Доступность книги на уровне `BookTitle` определяется агрегатно: книга считается доступной, если у нее есть хотя бы один `BookItem` со статусом `available`.

## 5. BookItem

Конкретный физический экземпляр книги.

### Поля

| Поле | Тип данных | Required | Auto-filled | Описание |
| --- | --- | --- | --- | --- |
| `id` | `BigAutoField` | Нет | Да | Уникальный идентификатор экземпляра книги |
| `book_title` | `ForeignKey` | Да | Нет | Ссылка на карточку книги `BookTitle` |
| `inventory_number` | `CharField` | Да | Нет | Уникальный инвентарный номер экземпляра |
| `status` | `CharField` | Да | Нет | Статус экземпляра книги |
| `location` | `CharField` | Нет | Нет | Место хранения экземпляра, опционально |
| `created_at` | `DateTimeField` | Нет | Да | Дата и время создания записи об экземпляре |
| `updated_at` | `DateTimeField` | Нет | Да | Дата и время последнего обновления записи об экземпляре |

### Возможные значения `status`

- `available` — доступна для выдачи
- `loaned` — выдана пользователю
- `unavailable` — временно недоступна для выдачи

### Связи

- один `BookItem` может иметь много записей в `Loan` во времени

### Примечание

- Именно `BookItem` участвует в выдаче, а не `BookTitle`.
- По `BookItem` можно понять, доступен ли конкретный экземпляр для выдачи.
- Для MVP обязательны поля `book_title`, `inventory_number` и `status`.
- `inventory_number` должен быть уникальным.
- Статус экземпляра обновляется при каждой операции выдачи и возврата, чтобы по `BookItem` можно было быстро определить доступность книги.

---

## 6. Loan

Факт выдачи конкретного экземпляра книги пользователю.

### Поля

| Поле | Тип данных | Required | Auto-filled | Описание |
| --- | --- | --- | --- | --- |
| `id` | `BigAutoField` | Нет | Да | Уникальный идентификатор записи выдачи |
| `user` | `ForeignKey` | Да | Нет | Ссылка на пользователя `User`, которому выдана книга |
| `book_item` | `ForeignKey` | Да | Нет | Ссылка на экземпляр книги `BookItem` |
| `issued_at` | `DateTimeField` | Да | Нет | Дата и время выдачи книги |
| `due_date` | `DateField` | Да | Нет | Ожидаемая дата возврата |
| `returned_at` | `DateTimeField` | Нет | Нет | Дата и время возврата, `null` если книга еще не возвращена |
| `created_at` | `DateTimeField` | Нет | Да | Дата и время создания записи выдачи |
| `updated_at` | `DateTimeField` | Нет | Да | Дата и время последнего обновления записи выдачи |

### Связи

- один `User` может иметь много записей `Loan`
- один `BookItem` может иметь много записей `Loan` во времени

### Бизнес-смысл

- хранит историю выдач
- позволяет понять, кто сейчас держит экземпляр
- позволяет отслеживать возвраты
- просрочка для MVP вычисляется по `due_date` и `returned_at`, без отдельного поля статуса

### Базовые правила

- выдать можно только `BookItem` со статусом `available`
- при выдаче статус `BookItem` меняется на `loaned`
- при возврате заполняется `returned_at`, а статус `BookItem` меняется на `available`
- у одного `BookItem` не должно быть более одной активной выдачи одновременно
- `due_date` не может быть раньше даты `issued_at`
- `returned_at` может быть `null` или датой/временем не раньше `issued_at`

### Политика удаления

- Для связей `ForeignKey` политика удаления задается через параметр `on_delete`.
- В MVP для критичных связей используется стратегия `PROTECT`, чтобы не разрушать историю выдач и структуру каталога.
- `BookItem.book_title` -> `on_delete=PROTECT`
- `Loan.user` -> `on_delete=PROTECT`
- `Loan.book_item` -> `on_delete=PROTECT`
- Связи `ManyToManyField` не используют `on_delete` напрямую.
- Ограничения на удаление `Author` и `Genre`, связанных с `BookTitle`, определяются бизнес-правилами приложения.

---

## Итоговая схема связей

- `User` 1 -> N `Loan`
- `Author` M <-> N `BookTitle`
- `Genre` M <-> N `BookTitle`
- `BookTitle` 1 -> N `BookItem`
- `BookItem` 1 -> N `Loan`

---

## Почему выбрана такая схема

- `BookTitle` хранит карточку книги в каталоге
- `BookItem` решает задачу учета физических экземпляров в рамках MVP
- `Loan` хранит историю движения экземпляров между библиотекой и пользователями
- схема остается простой, но уже отделяет каталог от учета выдачи

---

## Правила и ограничения MVP

- Для доступа к операциям выдачи и управлению каталогом достаточно использовать признак `is_staff`
- `BookTitle` создается только с заполненным `title` и хотя бы одним автором
- `Genre` в карточке книги является необязательным
- `isbn` может отсутствовать, но при наличии должен быть уникальным
- `BookItem` создается только с уникальным `inventory_number`
- `Loan` создается только для существующего `User` и доступного `BookItem`
- В системе не должно быть более одной активной выдачи на один экземпляр книги
- История выдач и каталог не должны разрушаться каскадным удалением связанных сущностей
